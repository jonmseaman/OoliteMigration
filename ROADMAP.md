# Oolite migration roadmap

Objective-C/GNUstep → C++23, native on Apple Silicon, Windows x64, and Linux x64, with all
published expansions working unmodified. **Start here.** Every other document is one link away.

**Status (2026-09-10):** planning complete. No code changes to `upstream/oolite`. Nothing built.
Decided 2026-09-10: every open decision taken by default ([ADR-0013](docs/decisions/0013-decide-up-front-minimise-human.md)); existing C is reused, not rewritten ([ADR-0012](docs/decisions/0012-c-stays-c.md)). Resequenced 2026-09-10: Apple Silicon moves after the runtime removal ([ADR-0009](docs/decisions/0009-apple-silicon-after-runtime-removal.md)); conversion targets C++20 ([ADR-0011](docs/decisions/0011-cpp20-then-cpp23.md)); one Windows machine until Phase 5 ([ADR-0010](docs/decisions/0010-single-windows-machine.md)). 2026-09-11: everything native on Windows, no WSL2; `upstream/oolite` is a subtree of the fork; Linux joins at Phase 5 ([ADR-0017](docs/decisions/0017-native-windows-subtree.md)).
**Status (2026-09-23):** Phase 0 done; Phase 1 done on branch `phase-1` (QuickJS-ng only; exit gate walked, Jon-owned items carried per ADR-0030); Phase 2 in progress on `phase-2`. Branches stack `phase-N` on `phase-(N-1)`; each is pushed to the fork as `migration/phase-N`.
**Current focus:** [Phase 0](docs/phases/0-safety-net.md). The beads queue exists (~695 beads across
Phases 0–4, generated by `tools/gen-stories.py`); `bd ready` lists the Phase 0 seams that can
start today. Before the first run on the Windows machine, work the [I0 checklist](docs/infra/0-machines.md). The Hermes worker ([I5](docs/infra/5-hermes-goal.md)) is configured but has nothing
labelled `fleet` that is ready until those seams land.

## Two tracks

**Migration track** — Phases 0–6, the work on the game. Sequential, except 1 ∥ 2. Everything
through Phase 4 runs natively on one Windows x86-64 machine; macOS and Linux join at Phase 5.
**Infra track** — I0–I5, the machine, its provisioning, the fleet, the metrics and the Hermes
runbook that let AI agents do the migration track. It gates Phase 0's exit and the first fleet sweep, and is worked in parallel.

Hardware and setup are infra items, not a migration phase: the agent host, build host, and
verification host are separate concerns, and the phase numbers stay stable.

With 1 and 2 in parallel, the conversion grind (Phase 3) starts at roughly month 8–14 and
**Apple Silicon lands after roughly 22–42 engineer-months**, on a codebase with no Objective-C left
in it. That is the cost of sequencing macOS after the runtime removal
([ADR-0009](docs/decisions/0009-apple-silicon-after-runtime-removal.md)); the benefit is that the
macOS build never carries Objective-C, `libobjc`, or Objective-C++ at all. Phases 0–2 still pay off
on their own (a maintained JS engine, no GNUstep) whether or not the conversion completes.

## Where Jon is

Exactly four places ([ADR-0013](docs/decisions/0013-decide-up-front-minimise-human.md)): the
weekly re-bless queue; accounts, credentials, hardware and TCC grants (including the one-time
[machine checklist](docs/infra/0-machines.md)); overriding a default decision by ADR; a monthly
judgement on whether the GUI tier still means something. Everything else, including every seam
and every merge, is an agent's job.

## Conventions

- Phase docs follow [templates/phase.md](docs/templates/phase.md). Status logs are append-only and
  dated. Record what the fleet could not do and a human did; that feeds `docs/fleet/FLEET_FAILURES.md`.
- Decisions are ADRs. Do not edit a decision in place; supersede it. An agent that needs a human
  decision files a proposed ADR with a default and proceeds on the default.
- Agent-facing docs have a token budget: `CLAUDE.md` ≤ 1k words, a phase doc ≤ 3k.
- `origin` is Jon's fork, `upstream` is the source project; rebase, don't merge
  ([architecture §6](docs/architecture.md)).
- The two original planning documents, `MIGRATION_PLAN.md` and `AI_EXECUTION_PLAN.md`, were
  dissolved into this tree on 2026-09-06. They are in git history at `ee2de41`.
