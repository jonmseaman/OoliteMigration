# Slice plan: ShipEntityAI

Pre-split for [Phase 3](../3-cpp-conversion.md) (bead oo-dfom). Checked by
`python3 tools/check-slice-plan.py docs/phases/3-slices/ShipEntityAI.md`, which
recounts the file every time, so the numbers below are only a snapshot.

- **File:** `Core/Entities/ShipEntityAI.mm` (2,986 lines) + header (77 lines). The legacy
  plist-AI surface of `ShipEntity`, as categories: `AI` (AI switching, the `perform*` behaviours,
  docking requests, wormholes, escorts, distress calls), `PureAI` (~150 methods that state-machine
  AIs call by name: scans, target and destination setters, checks, comms), `OOAIPrivate` (the
  hyperspace exit, predicate scans, distress handling) on `ShipEntity` and on `StationEntity`,
  and `OOAIStationStubs`, whose station-only methods on plain ships are generated by the
  `STATION_STUB_*` macros.
- **Shape:** `PureAI` alone is ~1,900 lines, so it is split in three by the order of the file,
  which already groups related actions. Many `PureAI` methods are called by name from AI plists
  (ADR-0043 item 21); converting them keeps their selectors reachable through the
  called-by-name table, exactly as the rest of `ShipEntity` does. The three whitespace /
  argument helpers have no Objective-C and stay verbatim
  ([ADR-0012](../../decisions/0012-c-stays-c.md), CLAUDE.md rule 9).
- **The stub block:** `OOAIStationStubs` is macro-generated, so the checker sees it as preamble
  (charged to every slice) rather than as units. Slice 1 converts it, with the other
  `OOAIPrivate` code.
- **Order:** after the `ooentity` pattern seam (oo-bj8) and once the `ShipEntity` class shell is
  C++ (frontier, oo-k8a, category by category). The slices only define `ShipEntity` /
  `StationEntity` members declared in the header or the preamble, so they are independent.
