# Upstream #792: Build the documentation with typst only, and make it optional

**Upstream:** hobleyd, merged 2026-11-08 as `4bb1f53de` (squash, parent `148575aab`) · **In the stack:** not in the stack
**Verdict:** Not in the stack (expected)

## What the PR changes

- The Markdown pages (`index`, `advice`, `privacy`, `LICENSE`) are rendered to PDF by typst with
  the vendored cmarker 0.1.10 (`Documentation/docs/typst/markdown.typ`, `docs/typst/vendor/cmarker/`).
  pandoc, WeasyPrint, Pango and the build-time `.venv` are no longer needed. `build_mds_fn.sh` and
  `build_documentation_fn.sh` change to match, and `build_documentation` loses its first argument.
  `build_mkdocs.sh` activates a `.venv` itself if there is one.
- New meson feature option `docs` (default `auto`) in `meson.options`. `src/meson.build` adds
  `find_program('typst', version: '>=0.15.0', required: get_option('docs'))` and passes
  `build_docs ? 'yes' : 'no'` as a new last post-build argument. `post_build.sh` reads it as
  `${13:-yes}` and skips the doc build when it is `no`.
- `install.sh` copies PDFs only if there are any.
- Removed: the pandoc and WeasyPrint install scripts (Linux and Windows),
  `ShellScripts/Linux/install_weasyprint.sh`, the Pango packages on every platform, the Flatpak
  pandoc and `python-weasyprint` modules, and the README step.
- CI and the Flatpak manifest pass `--setup-flags="-Ddocs=enabled"`, and CI no longer runs
  `install_weasyprint.sh`. ReadTheDocs leaves out the typst sources.

## What the stack would need to take it

1. Merge or cherry-pick `4bb1f53de` and resolve the three conflicts as above.
2. **Get the post-build argument index right.** With the merge, `src/meson.build` passes
   `build_docs` as the 12th argument, after `stamp_file`. If the conflict is resolved by taking
   #792's `${13:-yes}`, `build_docs` is always unset, so it defaults to `yes`. Then
   `-Ddocs=disabled`, and `auto` without typst, would still try to build the docs, and the build
   would fail at post-build. That is the bug #792 fixes (#791). It must read `${12:-yes}`.
3. Decide on the fork-only `unit-tests-windows` job (`build-all.yaml:450-547`, `./mk.sh build test
   --ccache --setup-flags="-Db_lto=false"`). #792 does not know this job exists. With `auto` and
   typst installed by `install_deps.sh`, the job still builds the PDFs, which is harmless. Adding
   `-Ddocs=disabled` would save time. Keeping `auto` is the conservative choice.
4. Flatpak: the merged manifest has typst only and `-Ddocs=enabled` on its `mk.sh flatpak` line
   (merged tree, `space.oolite.Oolite.yaml:26-32,67`). It also still has the fork's QuickJS-ng
   wrap source. `create_flatpak_fn.sh` still copies `python-weasyprint.*`, which #792 deletes from
   upstream too, so nothing more is needed.
5. Nothing in the C++ code or `tests/` is affected. `tests/run.sh` has its own `build/.venv-tests`,
   which is not the doc `.venv`.

## Tests

None in `oolite-dev/tests`. CI's build jobs, with `-Ddocs=enabled`, would be the check, together
with a local `-Ddocs=disabled` build to confirm the argument index (item 2).

## Findings

1. Applying #792 needs a manual merge in three files, all caused by the fork's GNUstep/SpiderMonkey
   removal and its CI rewrite. The one place a careless resolution breaks behaviour is the
   `post_build.sh` argument index (item 2 above): it must be `${12:-yes}` at HEAD's argument
   layout (`src/meson.build:47-59`; `stamp_file` is `${11}` at `post_build.sh:15`).
2. Until #792 is taken, every build of the stack needs pandoc, WeasyPrint, typst and a `.venv`
   (`Documentation/build_documentation_fn.sh:25-29`). Distro source builds hit exactly that in
   #791. The fork's own CI installs them all (see `pr-784.md`).

## Why this verdict

#792 was merged upstream after the stack's base `148575aab`, so its absence is expected
(`git merge-base --is-ancestor 4bb1f53de HEAD` fails). It does not apply cleanly. The three
conflicts are mechanical, but the `post_build.sh` one needs care so that the `docs` option works.
