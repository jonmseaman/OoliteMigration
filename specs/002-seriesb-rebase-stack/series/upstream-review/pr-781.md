# Upstream #781: macOS: keep the high-resolution Dock icon; document Developer ID signing (#779)

**Upstream:** David Hobley (hobleyd), merged 2026-10-29 as `d290865ec` · **In the stack:** base; the C++ conversion of `MyOpenGLView` carries the guard, and fork commit `167118dff` ("Port upstream #766, #774 and #781") records it
**Verdict:** Ported correctly (macOS runtime not verifiable here)

## What the PR changes

- `src/SDL/MyOpenGLView.m`: skip loading `Images/WMicon.bmp` and calling `SDL_SetWindowIcon` on
  macOS (`#if !OOLITE_MAC_OS_X`), so SDL does not replace the bundle's 1024×1024
  `oolite-icon.icns` Dock icon with the 32×32 bitmap. Linux and Windows unchanged. The local
  variables move inside the guarded block.
- `ShellScripts/macOS/create_app_bundle_fn.sh`: a comment above `sign_app_bundle` on what
  Developer ID signing and notarisation need. Signing itself is unchanged (ad-hoc).
- `.github/workflows/build-all.yaml`: the same note above the macOS `Package Oolite` step.

tree `OOLITE_MAC_OS_X` no longer exists (`grep -rn OOLITE_MAC_OS_X src` finds nothing), and
`OOLITE_MACOS` is the macro every other macOS block uses (see pr-766.md).

## Why this verdict

The guard is equivalent: on a macOS build the icon code is compiled out, and on Linux and Windows
it runs unchanged; both comments are present verbatim. Whether the Dock then shows the `.icns` icon
is macOS runtime behaviour that cannot be checked on this Windows host; the code that decides it is
the same as upstream's.
