1. **Format specifiers (about 45 files, ~150 hunks).** `%llu`/`%lu`/`%lld` -> `%zu`/`%zd` for
   `NSUInteger`/`NSInteger` arguments, often dropping a `(unsigned long)` cast. Most are log
   messages; the ones whose text is used as data are GUI row keys (`More:%zd`, `More:%zu`,

   truncated 0.34 to 0, so `q = activity.location + rv0 * activity.length` started at 0. Replaced

   `hdrPaperWhiteControlPressed` declared only under `#if OOLITE_WINDOWS`.
4. **Exact-width integer types** for `uint_fast*_t` / `int_fast*_t` (sign-compare and
   conversion warnings): `OOPixMapDimension` (`OOPixMap.h`), `OOECMBlastEntity._blastsRemaining`,
   `Octree` builder `_nodeCount`, `_capacity`, `_level`, `OOMeshToOctreeConverter` `count`,
   `capacity`, `pendingCapacity` and its loop counters, all locals in `OOTextureScaling.m` and
   `OOPixMapChannelOperations.m`, `OOProfilingStopwatch.m` `deltaS`/`deltaU`,
   `legacy_random.c` `rotate_seed` `x`/`y`. Three casts dropped with them
   (`ModulatePixMap_4`'s `(uint_fast32_t)m0 << 24`, two in `OOMeshToOctreeConverter.m`).
   `uint_fast64_t` in `OOTextureScaling.m` is left as it was.
5. **Warning suppression added.** `#pragma clang diagnostic ignored
   "-Wobjc-protocol-method-implementation"` around the `NSBundle (Override)` and
   `NSUserDefaults (Override)` categories and `-[NSObject description]` in `OOCocoa.m` (later made
   Clang-only by #736).
6. **Macro clash.** `OOJSEngineTimeManagement.m`: `#undef __block` before redefining it.

## Findings

1. Inherited from upstream, not a regression: `OOTCPStreamDecoder.cpp:164-169` passes
   `(unsigned long)` arguments to `%zu`. The fork's formatter reads `%zu` as `size_t`
   (`src/Core/Debug/OOTCPStreamDecoderFormat.hpp:6-7`), so on Windows (LLP64, 32-bit `long`) the
   two values and the following `%@` are read from the wrong slots. It is the "reached unreachable
   state" error path. Upstream #734 introduced the mismatch by changing `%lu` to `%zu` and keeping
   the casts; the fix is to drop the casts (as upstream did elsewhere).
2. `OOPixMapChannelOperations.cpp:293`: `m0 << 24` with `m0` a `uint16_t` promotes to `int`; for
   `m0 >= 128` that overflows `int`. Upstream compiles this as C (undefined); the fork compiles it
   as C++20, where the shift is defined and gives the same bits. Same output as upstream; noted only
   because #734 removed the cast that made it unsigned.
3. `OOLogHeader.cpp` uses `%llu` where upstream wrote `%zu`, matching the `unsigned long long`
   values actually passed. macOS-only code; output text is the same.

## Why this verdict

Every behavioural hunk (the wormhole fix, the Windows-only statics, the integer retyping, and the
format strings whose output is used as a key) is present at HEAD with the same types and the same
produced text. Hunks tied to GNUstep, SpiderMonkey-era statistics or Objective-C categories went
with that code. No suppression replaced a fix. The one questionable hunk (finding 1) is upstream's
own and is carried unchanged.
