# Upstream #730: Split MyOpenGLView into two

**Upstream:** mcarans, merged 2026-09-06 as `4b0d5cbcf` · **In the stack:** base (below the conversion); carried by the `MyOpenGLView` conversion
**Verdict:** Ported with deviations

## What the PR changes
- Moves the input half of `MyOpenGLView` (key mapping, string input, mouse state, `-pollControls`,
  `-handleStringInput:keyID:`, `-setMouseInDeltaMode:`) out of `MyOpenGLView.m` into a new
  `MyOpenGLView (Input)` category, `src/SDL/MyOpenGLView+Input.{h,m}`, and adds the `.m` to
  `src/SDL/meson.build`.
- Removes dead code: `-indexOfCurrentSize`, `-pngSaveSurface:withSurface:` (under
  `SNAPSHOTS_PNG_FORMAT`) and `-translateKeyCode:` (Cocoa `NS*FunctionKey` mapping). None had a caller.
- Makes `-updateGLSize:` public and drops `-bounds` from the header.
- No other behaviour change; the moved code is otherwise identical (checked by diffing the removed
  and added lines with whitespace stripped: the only removed-only lines are the three dead methods).

## Findings
1. **Double-click is timed by the event, not the poll** (deliberate fork change, in code #730 moved).
   Upstream base takes the click time from `timeNow`, sampled once at the start of the poll
   (`148575aab:src/SDL/MyOpenGLView+Input.m:276`). HEAD uses the release event's own timestamp,
   `mbtn_event->timestamp / 1e9` (`src/SDL/MyOpenGLView+Input.cpp:253`), and starts
   `timeIntervalAtLastClick` on the same `SDL_GetTicksNS()` clock (`src/SDL/MyOpenGLView.cpp:500`).
   A stalled poll no longer turns a double-click into two single clicks. Pinned by
   `tests/gui/test_double_click_timing.py`.
2. **Key array bound tightened from `<=` to `<`.** Upstream writes `keys[key_id]` when
   `key_id <= [self numKeys]` on key down and key up (`148575aab:...+Input.m:623`, `:806`);
   `keys` has `NUM_KEYS` (327) entries, so `key_id == 327` writes one past the end. F12 sets
   `key_id = 327` (`...+Input.m:575`, `:792`), so every F12 press is an out-of-bounds write upstream.
   HEAD checks `key_id < numKeys()` (`src/SDL/MyOpenGLView+Input.cpp:619`, `:813`): F12 still
   toggles the screen mode (`:562`) but its key state is not stored, and key down logs
   `keys.test` "Unhandled Keydown scancode/unicode". Nothing reads `keys[327]`, so the only
   observable difference is that log line. Came in with the conversion (`9304fedba`).

## Why this verdict
The split itself is a pure move plus dead-code removal, and HEAD has the same split
(`MyOpenGLView.cpp` / `MyOpenGLView+Input.cpp`) with the same event handling and none of the
removed methods. The two differences in the moved code are fork fixes (an event-timestamp
double-click and an out-of-bounds write avoided), not losses, so the PR's behaviour is kept with
deviations rather than regressed.
