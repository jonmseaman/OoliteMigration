# Upstream #784: Include documentation in builds

**Upstream:** mcarans, merged 2026-11-04 as `9090a654b` (squash) · **In the stack:** base (ancestor of `148575aab`)
**Verdict:** Ported correctly

## What the PR changes

- Every build makes the PDFs: `post_build.sh` sources `Documentation/build_documentation_fn.sh` and
  calls `build_documentation "YES" "NO"` (no Doxygen), then copies
  `build/documentation/docs/assets/pdfs/*` into the app folder. On macOS they go to a
  `Documentation` folder next to the bundle, since files in the bundle root break its signature.
- The reference sheet moves from `Doc/OoliteRS.odt` to Typst (`Documentation/docs/typst/*.typ`).
  The Markdown pages move to `docs/md/` and are turned into PDFs with pandoc and WeasyPrint.
  `build_mds_fn.sh`, `build_referencesheet_fn.sh`, `build_mkdocs.sh` and `build_readthedocs.sh` are added.
- Installing and packaging: `install.sh` copies `*.pdf` into the data dir. NSIS no longer downloads
  the PDFs from readthedocs; it copies them from the build folder and leaves `*.pdf` out of its
  recursive `File`. `create_dmg_fn.sh` adds the `Documentation` folder. Flatpak gains pandoc, typst
  and `python-weasyprint.json` modules.
- Dependencies: Linux gets `doxygen`, `weasyprint-deps`, `python3-venv`, pandoc, typst and
  `install_weasyprint.sh` (a `.venv`). Windows `install_deps.sh` gets the pandoc, WeasyPrint and
  typst installers and the Pango/Cairo packages. macOS gets `doxygen graphviz pandoc typst weasyprint`.
  `install_gitversion` takes an install dir.
- CI: `install_weasyprint.sh` runs in each Linux job.
- Unrelated fix: on Windows `strip "$progpath.exe"`.

## Tests

None. No test in `oolite-dev/tests` builds or checks the PDFs (`grep -rln -iE
'build_documentation|\.pdf' tests` finds only a comment in `tests/gui/test_g11_*`). CI's build jobs
are the only check: post-build fails if `build_documentation` fails.

## Findings

1. Every CI build job that runs post-build installs the doc toolchain: the appimage, ubuntu and
   fedora jobs through `install_weasyprint.sh`, the windows jobs (including the fork-only
   `unit-tests-windows`) through `install_deps.sh`, and macOS through `install_packages.sh`.
   Flatpak skips the `.venv` because of `FLATPAK_BUILDER_BUILDDIR`. So the fork's new CI jobs do
   not break the doc build's `.venv` requirement (`Documentation/build_documentation_fn.sh:25-29`).
2. `specs/002-seriesb-rebase-stack/upstream-prs.md:44` is stale. It says "not yet / T077", but #784
   is in the stack's base (`git merge-base --is-ancestor 9090a654b HEAD` succeeds). The same table
   still gives `7437f22a5` (#780) as the base.

## Why this verdict

#784 is below the conversion and touches only scripts, installers, CI and docs. The conversion
removed GNUstep and SpiderMonkey from these same files but left every hunk of #784 in place. The
one cross-cutting change, dropping the `gnustep_folder` post-build argument, was made in both
`src/meson.build` and `post_build.sh`, so the argument positions still agree.
