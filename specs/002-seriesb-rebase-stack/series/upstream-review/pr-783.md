# Upstream #783: Adds ability to use joystick on GUI screens

**Upstream:** phkb, merged 2026-11-03 as `28ceaaba0` (commits `82705fe48`, `38aa005d3`) · **In the stack:** ported at step 022 (`e46db2373`), with later fixes `d94938de9`, `94d84a1b5`, `17df552aa`, `6427b0e4e`, `e9f650380`, `a42f62073`, `3bf88dac7`
**Verdict:** Ported with deviations

## What the PR changes

- `OOJoystickManager` gets seven new button functions, `BUTTON_GUILEFT` .. `BUTTON_GUISELECT`, placed before `BUTTON_end`, and a second button table, `guibuttonmap`. It adds `setGuiFunctionForButton`, `unsetGuiButtonFunction` and `guiButtonFunctions`. `setFunction:withDict:` sends a button function in the GUI range to the GUI table. The table is saved and loaded under the `GuiJoystickButs` defaults key.
- `OOSDLJoystickManager`'s button decoder looks up `guibuttonmap` as well and sets `butstate[guifunction]`. One physical button can therefore drive a flight function and a GUI function at the same time.
- `PlayerEntityControls`: wherever a GUI screen checks `n_key_gui_{arrow_up,arrow_down,arrow_left,arrow_right,page_up,page_down,select}`, it also checks the matching `joyButtonState[BUTTON_GUI*]` (14 functions get a `joyButtonState` local). `clearStickStates` is called when entering the stick and key mapper from game options, at the end of the key-mapper, keyboard-layout and stick-mapper handlers, and at the end of the INTRO1 case.
- `PlayerEntityKeyMapper` (4 handlers) and `PlayerEntityLoadSave` (commander selector, save, overwrite): select, left/right and page keys also accept the joystick GUI buttons.
- `PlayerEntityStickMapper`: select is `n_key_gui_select || BUTTON_GUISELECT || double-click` instead of `isDown:13`. Assigning a GUI function skips `checkCustomEquipButtons`. The list shows a GUI function's assignment from `guiButtonFunctions`. A "GUI controls" section is added with the seven functions.
- `descriptions.plist`: `stickmapper-gui-*` (7) and `stickmapper-header-gui`.

## Findings

1. **Deliberate deviation: `clearMappings()` resets `guibuttonmap`** (`OOJoystickManager.cpp:450-458`, `d94938de9`/`94d84a1b5`). Upstream resets only `axismap` and `buttonmap` (`28ceaaba0:src/Core/OOJoystickManager.m:420-424`), so the GUI table starts all 0, and 0 is `BUTTON_INCTHRUST` (`OOJoystickManager.h:76`). Three things follow upstream:
   - Every unassigned button also drives increase-thrust, through the decoder's `guifunction >= 0` branch.
   - `guiButtonFunctions()` saves a `"0"` entry pointing at the last stick's last button.
   - On reload, `setFunction(0, …)` sends that entry to `setFunctionForButton`, because 0 is outside the GUI range, which takes the player's real increase-thrust binding away.

   The fork's behaviour is the one #783 intended. The step doc already flags it as a fix upstream may want. This is not a regression.
2. **Upstream quirk kept: `handleKeyboardLayoutKeys`.** #783 adds the joystick GUI buttons only to `leftRightKeyPressed`. The inner right/page-down and left/page-up checks still test only the keys. The fork has the same code (`PlayerEntityControls.cpp:4262-4275`), so a joystick GUI left/right on that screen re-shows the page of the selected row instead of paging. The fork matches upstream here.
3. **Upstream quirks kept: `selectPressed` keys only.** INTRO1's `selectPressed = checkKeyPress(n_key_gui_select)` (`PlayerEntityControls.cpp:5320`) does not include the joystick, and #783 left it that way, while the NEWGAME and OXZMANAGER `selectPressed` assignments do include it. Likewise `unsetGuiButtonFunction` is never called by the stick mapper, so a GUI function can't be unassigned from the UI, only reassigned. Both match upstream.
4. **#786 interaction is correct.** #786 (`09ef336e7`, in the stack) moved the stick mapper's literals into `descriptions.plist`. HEAD's `descriptions.plist` matches upstream base `148575aab` exactly (`git diff 148575aab HEAD -- Resources/Config/descriptions.plist` is empty), so both #783's eight keys and #786's keys are present.
   - All 24 `DESC` keys #786 adds to the stick mapper are used in `PlayerEntityStickMapper.cpp`. In the `HW_BUTTON` branch the `#786` `stickmapper-allowed-button` sits beside #783's GUI-table lookup (`:536-545`).
   - `3bf88dac7` and then `a42f62073` made `stickMapperHardwareAndGuiDicts` expect `hwToString`'s names from the descriptions table (the test supplies the three entries, since its universe loads no descriptions). The commits record that Jon approved both test changes.

## Why this verdict

Every hunk of #783 has an equivalent at HEAD, with one exception: the `!NEW_PLANETS` hunk, which is dead code upstream. In all four `PlayerEntity*` files the order of GUI-key checks, joystick GUI-button checks and `clearStickStates` calls matches upstream token for token. The single behavioural difference is the deliberate `clearMappings()` reset. It fixes an upstream bug (unassigned buttons driving increase-thrust, and save/reload unbinding increase-thrust), and unit tests pin it. Hence "Ported with deviations" rather than "Ported correctly". Nothing regresses.
