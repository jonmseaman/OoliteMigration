## Tests

The job itself is the check. `build-ubuntu` and `build-fedora` do not depend on it, as upstream's
did not at the base `148575aab`.

## Findings

1. On a pull request opened from a branch of the same repository the fork skips
   `clang-format-check` (the push event already ran it), and GitHub then skips every job that
   `needs` it, so such a PR shows the builds as skipped rather than run twice. A PR from a fork runs
   it as upstream does. This is the fork's de-duplication, applied the same way to `oxp-upgrade`,
   `build-ubuntu` and `build-fedora` (`:33`, `:150`, `:230`), not a lost check: every push is still
   checked.

## Why this verdict

The check is the same action, version and path, and still gates the package builds. The fork adds
an event filter and a timeout, gates two more jobs, and checks its own Google style instead of
WebKit; none of that weakens the check upstream added.
