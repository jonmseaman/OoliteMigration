# Upstream #737: Rename OOCocoa to OOFoundation and remove some crud

**Upstream:** mcarans (Mike), merged 2026-09-15 as `822d4a9b5` (squash) · **In the stack:** base; the conversion steps' own new comments were brought in line by `f18e064bc`, `037cf9049`, `8f62d84da`, `404b8369c`, `a4d0a10cb`, `5b609646a`
**Verdict:** Ported correctly

## What the PR changes

85 files. Every hunk outside the five files below is a one-line
`#import "OOCocoa.h"` -> `#import "OOFoundation.h"` (checked by filtering the diff: the only other
`+`/`-` line pair is the comment in `OOJavaScriptEngine.h`). The non-rename hunks:

- `src/Core/OOCocoa.h` -> `OOFoundation.h` (and `.m`), with `meson.build` compiling
  `OOFoundation.m`.
- Removed from the header: the `NSIntegerMax`/`NSIntegerMin`/`NSUIntegerMax` fallback for
  GNUstep < 1.23; the Mac branch's `<AppKit/AppKit.h>` import, `OOLITE_SPEECH_SYNTH 1`,
  `OOLITE_64_BIT` on `__LP64__`, `OOLITE_MAC_OS_X_10_7` / `_10_8` and the `NSWindowStyleMask`
  typedef; the `OOLITE_HAVE_PROTOCOL_OPTIONAL` hack (`OOLITE_OPTIONAL` becomes plain `@optional`).
- `OOOXZManager.m`: the 10.7-conditional `NSURLConnectionDataDelegate` protocol declaration
  becomes the informal category in all builds.
- `OOJavaScriptEngine.h`: comment names `OOFoundation.h`.
- Deleted `src/Core/GameController+FullScreen.m` (Mac-only, not in `meson.build` before the PR).

On the GNUstep/SDL builds that upstream ships for Windows and Linux none of this changes
behaviour: every removed macro was either Mac-only or a fallback for a GNUstep older than the
1.28 the header already required.

## Tests

None pin the rename itself; a missing or misnamed header would fail the build.
`tests/unit/oofnd/test_foundation_types.cpp:63` checks `NSIntegerMax`, which is now unconditional.

## Findings

1. Cosmetic: `src/Core/OOFoundation.cpp:3` still names the file `OOFoundation.m` in its header
   comment. That is upstream's post-#737 name; the conversion renamed the file but not the comment.
   No behaviour.
2. Cosmetic: five test comments still say `OOCocoa.h` (`tests/unit/core/test_OODebugMonitor.cpp:52`,
   `test_OODebugSupport.cpp:51`, `test_OOJavaScriptEngine.cpp:890`, `test_OOSunEntity.cpp:242`,
   `tests/unit/oofnd/test_cocoa_macros.cpp:4`). They describe the `true`/`false` macros, which the
   current `OOFoundation.h` no longer defines. Comment only; test files are left in place by rule.

## Why this verdict

Every behavioural hunk of #737 deletes Mac-only or obsolete-GNUstep code, and HEAD has none of
that code left (no `OOLITE_MAC_OS_X`, no AppKit, no protocols, no `NSURLConnection`). The
surviving platform macros (`OOLITE_64_BIT`, `OOLITE_SPEECH_SYNTH`) are defined exactly where
upstream's post-#737 header defines them for SDL builds. The rename is complete in `src/`; two
stale comments are the only leftovers.
