# Upstream #786: Moves more text into descriptions.plist for easier localisation

**Upstream:** phkb, merged 2026-11-05 as `09ef336e7` (one commit, `040599229`) · **In the stack:** base (below the conversion; carried through every step and the `.m` -> `.cpp` rename at `ff8664462`)
**Verdict:** Ported correctly

## What the PR changes

- Adds 34 keys to `Resources/Config/descriptions.plist`: `oolite-hud-distance-unit`, nine
  `oolite-keyconfig-*` keys and 24 `stickmapper-*` keys.
- Replaces every hardcoded English string on the keyboard-config, keyboard-layout and stick-mapper
  screens with a `DESC()` lookup. It also uses the existing `oolite-keyconfig-update-key` in place of
  the `DESC(@"Key: %@")` format.
- HUD: reads `oolite-hud-distance-unit` once when the HUD is initialised (a file-static
  `distance_unit`) and uses it in place of `km` in the target-reticle and waypoint range lines.

## Findings

None that is a regression.

1. Minor improvement, not a deviation. Upstream assigns an autoreleased `DESC()` result to a static
   `NSString*` without retaining it. HEAD stores a `std::string` copy (`HeadUpDisplay.cpp:274, 455`),
   so the dangling-pointer risk upstream has is gone. Like upstream, the value is re-read each time a
   HUD is initialised.
2. `specs/002-seriesb-rebase-stack/upstream-prs.md:46` still lists #786 as "**not yet**" (T077). That
   is out of date: the PR is in the stack's base and its behaviour is present at HEAD.

## Why this verdict

All 27 string sites that #786 moved to descriptions use the same key at HEAD, with the same format
shape (`"%s '%s'"`, `"%s %d %s %d"`, `"%0.3f %s"` and so on). That includes the hat-direction order.
All 34 keys it added, plus the existing `oolite-keyconfig-update-key`, are in `descriptions.plist` at
HEAD with upstream's values. The conversion did not bring back any of the old literals. The only test
change was to `stickMapperHardwareAndGuiDicts`, which Jon approved to follow upstream's behaviour.
