# Upstream #756: Debug monitor enabled in release build

**Upstream:** Mike (mcarans), merged 2026-10-25 as `9ee8ff22f` · **In the stack:** base; the guards are carried through every conversion step (fork commits `a4d0a10cb`, `404b8369c`, `8f62d84da`, `f18e064bc`, then each class's conversion), and step 021 adds `tests/check_debug_monitor_guards.py`
**Verdict:** Ported correctly

## What the PR changes

- **Build:** a new `OO_DEBUG_MONITOR_ENABLED` macro. The deployment flavour defines it (and now
  `OO_OXP_VERIFIER_ENABLED=1`) alongside `NDEBUG`; other flavours define it when the new meson
  option `oo_debug_monitor_enabled` (default true) is on.
- **Guards:** about 150 `#ifndef NDEBUG` blocks around debug-monitor code become
  `#ifdef OO_DEBUG_MONITOR_ENABLED` in 70 source files (console, TCP client and decoder, monitor,
  entity counts and dumps, linked-list checks, texture/material/drawable dumps, JS console globals,
  time acceleration, octree/normals drawing, `gDebugFlags`). Special forms:
  `#if OO_SHADERS || defined(OO_DEBUG_MONITOR_ENABLED)` (shader uniform binding),
  `!defined(OODEBUGLDRAWING_DISABLE) && !defined(OO_DEBUG_MONITOR_ENABLED)` (debug-GL stubs),
  `#ifndef OO_DEBUG_MONITOR_ENABLED` stubs in `OODebugStandards` and `OOOXZManager`,
  `OOJSENGINE_MONITOR_SUPPORT` = `OO_DEBUG_MONITOR_ENABLED`, and
  `OOLITE_DEBUG || defined(OO_DEBUG_MONITOR_ENABLED)` for `OOJSDumpStack` and the string expander's
  syntax `WARNINGS`.
- **Standards enforcement default:** `STANDARDS_ENFORCEMENT_OFF` under `NDEBUG`, `WARN` otherwise
  (deployment builds stay quiet unless `enforce-oxp-standards` is set).
- **Packaging:** `post_build.sh` always copies `DebugOXP/Debug.oxp` as `AddOns/Basic-debug.oxp`;
  the manifest's `debug_functionality_support` follows the monitor option instead of
  `deployment_release`; `src/meson.build` passes the monitor option instead of `debug` and
  `deployment_release`.
- **Tests/CI:** `mk.sh test deployment` is no longer refused; `test_builds.yaml` builds, tests and
  packages `deployment` (plus a `dev` compile check).

## Findings

1. Outside #756's own hunks, but in code it guards: the entity memory figure the monitor reports is
   no longer an object size. `oo::EntityObjectSize()` returns `3 * sizeof(void*)` for every entity
   (`src/Core/Entities/EntityHelpers.h:68-71`), and it feeds `gTotalEntityMemory`
   (`EntityHelpers.cpp:100,115`, `Entity.cpp:132`), the entity dump's per-entity size
   (`OODebugMonitor.cpp:380-381`) and the memory line at `PlayerEntity.cpp:5094-5095`. Upstream used
   `class_getInstanceSize` of the entity's class (`NSObjectOOExtensions.m`, base), so a ShipEntity
   counted its full instance size. Low severity: debug output only. A `sizeof *this` virtual, as
   `OODrawable::objectSize()` already has (`OODrawable.h:80`), would restore it.

## Why this verdict

Every guard #756 changed is at HEAD with the same condition, either in the converted file or where
the code moved; the pieces that are gone (legacy `PlanetEntity`, the Objective-C size category,
retain-count tracing, SpiderMonkey declarations) went with code that the conversion removed
legitimately. The build flags, manifest, Debug OXP packaging and deployment testing are all present,
and a meson test pins the guard rule. The one difference found is in what a guarded statistic
measures, not in whether it is compiled in.
