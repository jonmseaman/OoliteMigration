# Upstream #768: Make QuickJS-ng the only JavaScript engine; remove SpiderMonkey

**Upstream:** hobleyd, open, head `cacb3c6a0` (updated 2026-11-10; 41 commits on `4bb1f53de`, #792) · **In the stack:** `seriesb/000b-upstream-768-quickjs-only` (tip `8b841c1ba`, the 7 Nov copy, on `148575aab`), carried through every conversion step
**Verdict:** Ported with deviations

## What the PR changes
The 7 Nov copy the stack carries (the stack's 000a + 000b, 30 commits):
- QuickJS-ng 0.17.0 as the only engine, built as a forced-fallback Meson subproject with Oolite's primitive-property patch; SpiderMonkey, `js_engine` and the Mozilla JS build scripts removed.
- The scripting layer on QuickJS-ng's API, with SpiderMonkey 1.8.5 emulation: scope-chain wrapping, prototype accessors reported as own properties, `toSource()`/`uneval()` (`oolite-quickjs-compat.js`), the `const`→`var` rewriter, `"use oolite modern"` opt-out, compiled-script cache, interrupt-handler time limiter, native profiler, debug console port, the global object converting to nil, `Vector3D.to/fromCoordinateSystem()`, deferred `quitGame()` + `script.javaScript.shutDown` leak check, Oolite warnings logged as `...warning.ooliteDefined`, Vector3D/Quaternion conversion statistics dropped.
- `tools/oxp-upgrade`, `tools/js-parity`, the `poc/` harness, flatpak sources, docs.

Added upstream since the stack's copy (the 9 Nov commits, now in both #767 and #768):
1. `fd0ca9304` error locations: take the first `(` of a stack frame, so `C:\Program Files (x86)\...` paths survive.
2. `f82ce9c24` `LogProblem()` returns early only for ignored *warnings*; errors and exceptions always reach the debug monitor.
3. `1a6df520b` compat script: arrays and objects share the `uneval()` visited list, so `o.list = [o]; uneval(o)` no longer overflows.
4. `7f8360baa` `textureDescriptorFromJSValue`: test String objects by class ID instead of converting the value.
5. `bbf13d7ca` make the const rewriter read-only (then replaced by 7).
6. `54cff258a` cache rewritten sources for the session, keyed by source text (~7 ms per 60 KB ship script otherwise, charged to the caller's time limit).
7. `ac0f8a3d3` delete every global SpiderMonkey 1.8.5 did not have (`Map`, `Symbol`, `Promise`, `globalThis`, `atob`, ...) at context creation; the compat script returns the const rewriter, which the engine keeps privately (`OOJSLegacyConstRewriter()`), instead of putting `__ooliteRewriteLegacyConst` on the global object.
8. `069aed7c6` new QuickJS patch `0002-oolite-new-on-native-functions.patch`: `new` on any generic C function works as in SpiderMonkey (`new Vector3D.random()`); the unpatched-engine check also tries `new Math.max()`.
9. `16e5f84be` Timer: no `script.javaScript.unrootedTimer` warning for a one-shot timer freed inside its own callback.
10. `18c6f8739` README: lists the `debugger;`, conversion-counter and `<console input>` differences.

The three 22 Oct commits (`3d0e99503`, `f94bba420`, `8b841c1ba`) moved from #768 into #767 upstream with identical content, only re-pathed under `src/Core/Scripting/QuickJS/` (`git range-diff 148575aab..8b841c1ba 4bb1f53de..refs/review/pr768`). The other 768-only commits differ only in CI context (#792 rebase) and the second patch file listed in the flatpak manifest and README.

## Findings
1. **The stack's #768 is three days stale.** Changes 1–3 and 5–9 are not at HEAD. If upstream merges the current #768 and then takes the stack, those fixes would be reverted. None is a conversion loss; the stack simply predates them. 8 matters most to players: without it `new Vector3D.random(...)` throws "not a constructor" (upstream cites Griff's ships).
2. **Porting is small and mostly mechanical.** The compat-script hunks apply verbatim (the file is untouched since `8b841c1ba`). Patch 0002 applies to the fetched 0.17.0 source with offset −3 (`patch --dry-run -p1` in `subprojects/quickjs-0.17.0`, which is unpatched). The fork's other quickjs.c patches touch other hunks (void-return at line 5006, 0001 at 10732; 0002 is at 21081), so it should stack after them; add it to the wrap's `diff_files`. The fork's flatpak fetches the tarball into `packagecache` and lets Meson apply the patches (`installers/flatpak/space.oolite.Oolite.yaml:86-93`), so unlike upstream it needs no extra manifest entry. The C++ edits go at the HEAD lines in the table: `rfind`→`find`; `severity == "warning" &&`; a `static std::unordered_map<std::string, std::string>` in `RewriteLegacyConst`; a `_firing` member set around `callJSFunction` in `OOJSTimer::timerFired()` (`OOJSTimer.cpp:222`) and checked with `interval() <= 0` (`OOScriptTimer.h:85`) in `clearJSSelf`; `RemoveNonSpiderMonkeyGlobals()` after `JS_GetGlobalObject` at `OOJavaScriptEngine.cpp:183`, keeping the compat script's result in `LoadCompatibilityScript` and freeing it at reset (`:243`).
3. **Porting change 7 will fail one existing test**, which needs updating under the upstream-behaviour exception. `tests/unit/core/test_OOJavaScriptEngine.cpp:807` evaluates `delete globalThis.vault` through the real engine (`tests/unit/core/meson.build:24` links the whole game; `SetUp()` calls `OOJavaScriptEngine::sharedEngine()`). Once `globalThis` is deleted, that becomes a TypeError. Use `global.vault` there. The other unit tests that use `globalThis` (`test_OOJSTimer`, `test_OOJSFrameCallbacks`, `test_OOJSFunction`, the three definition tests) make their own `JS_NewContext` and are unaffected. The comment at `OOJavaScriptEngine.cpp:1867` also names `globalThis`.
4. **Fork-only interplay to check after porting change 7.** The fork's `Resources/Scripts/oolite-global-prefix.js` (`5a06057f6`: `String.prototype.quote()`, Array/String generics) uses none of the removed globals (`grep -n 'globalThis\|Map(\|Symbol\|Promise' Resources/Scripts/*.js` hits only the compat script and the word "CurrencySymbol"). No fork code is known to depend on the removed globals.
5. **The 59 "(#580)" fork commits are all upstream's (author David Hobley), none the fork's own.** 30 are this copy (000a+000b, `148575aab..8b841c1ba`). The other 29 (`7437f22a5..db4920103`) are an earlier copy of the same branch, based on #780, that step 001 was first built on: `ebd84f7c4`'s parent is `db4920103`. The 7 Nov copy was merged in at `c6fe941e2` after `74da92545` ("Take the 7 Nov 2026 version of upstream PR 768"). `git range-diff 7437f22a5..db4920103 148575aab..8b841c1ba` shows the two copies as patch-identical, apart from CI-file context and the one commit missing from the older copy (`4fc77cd99`, a profiling comment). Because both copies are in HEAD's history, the stack's log shows each #580 commit twice.
6. Upstream's #767/#768 now sit on `4bb1f53de` (#792), which the stack does not have. Refreshing 000a/000b to the new heads would bring #792 into the stack.

## Why this verdict
The scripting behaviour of the copy the stack carries survives the C++ conversion. Every spot-checked behaviour is at HEAD, with tests for the primitive patch, the leak check, coordinate systems and the const rewrite; the only differences are in the wrap's build form. But upstream has since added eight behavioural fixes (and a doc note) that HEAD lacks, and one more that HEAD reached on its own. This is not a conversion regression, but taking the stack as it is would lose them, so the verdict is deviations. Porting them is a few dozen lines plus one test update.
