# Upstream #742: Fix OOJoystickManager decodeButtonEvent warning on GCC

**Upstream:** mcarans (Mike), merged 2026-09-17 as `663dd2a99` (squash) · **In the stack:** base; layout kept by the conversion (003), C++ classes at 010 (`a7764d6a9`); `test_OOJoystickDecoding` pins it
**Verdict:** Ported with deviations

## What the PR changes

Fixes upstream issue #661. Four files (`OOJoystickManager.h/.m`, `OOSDLJoystickManager.h/.m`):

- Removes the abstracted `JOYAXISMOTION`/`JOYBUTTONDOWN`/`JOYHAT_*` enum and the
  `JoyAxisEvent`/`JoyButtonEvent`/`JoyHatEvent` types (SDL typedefs, or hand-made structs on
  non-SDL builds) from `OOJoystickManager.h`; SDL is assumed.
- Moves `decodeAxisEvent:`, `decodeButtonEvent:`, `decodeHatEvent:` from `OOJoystickManager` to
  `OOSDLJoystickManager`, taking `SDL_JoyAxisEvent*` / `SDL_JoyButtonEvent*` / `SDL_JoyHatEvent*`.
  Bodies unchanged except that `JOYBUTTONDOWN`/`JOYBUTTONUP` become
  `SDL_EVENT_JOYSTICK_BUTTON_DOWN`/`_UP`.
- `make*Event:` return the SDL types.
- `STICK_DEADZONE` is 0.05 on every platform (the macOS branch had 0.0025).
- `joystickCount` moves to the "override in subclasses" group (base returns 0; SDL returns
  `stickCount`); `nameOfJoystick:` and `getAxisWithStick:` move up in the SDL file.
- Ivar visibility: `roll_profile`/`pitch_profile`/`yaw_profile` become the only `@private` ivars,
  so the subclass's decoders can reach the mapping arrays.

## Findings

1. Deviation, a fix: upstream (before and after #742) stores `getJoystickIndexFromId`'s `-1` for an
   unknown stick in `SDL_JoyAxisEvent.which`, an unsigned `SDL_JoystickID`, so `joyEvt.which >= 0`
   is always true and the decoders index `axismap[which]` / `buttonmap[which]` / `hatstate[which]`
   with `0xFFFFFFFF`. #742 made this more direct by switching to the SDL types, but the bug predates
   it. The fork tests the index itself (introduced at 010, `a7764d6a9`), so an event from a stick
   the manager did not open is refused and `handleSDLEvent` returns false. Pinned by
   `refusesEventsOfAStickItDidNotOpen`.
2. Carried unchanged from upstream: gamepad button events (`SDL_EVENT_GAMEPAD_BUTTON_DOWN/UP`) are
   cast to `SDL_JoyButtonEvent` and `decodeButtonEvent` compares only against
   `SDL_EVENT_JOYSTICK_BUTTON_DOWN`, so a gamepad button-down records as up. Same at HEAD
   (`OOSDLJoystickManager.cpp:134-145`, `:258`) as in upstream. Not this PR's change; noted for
   upstream.

## Why this verdict

Everything #742 moved or removed is where it put it, with the same bodies, and the single dead zone
is pinned. The one difference is the dispatch guard, which the fork tightened to stop an
out-of-bounds index on hot-plugged sticks. That changes observable behaviour (stray events are
dropped), so the verdict is "with deviations", not "correctly".
