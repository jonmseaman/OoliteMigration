# Upstream #758: Clang 23 and deployment build fixes

**Upstream:** mcarans, merged 2026-10-10 as `574ca848c` (squash) · **In the stack:** base (ancestor of `148575aab`)
**Verdict:** Ported correctly

## What the PR changes
- Bumps the pinned libobjc2, tools-make and libs-base commits in `ShellScripts/Linux/build_gnustep.sh` and the flatpak manifest, for Clang 23 (upstream issue #759).
- `ShellScripts/Linux/dep_location_fn.sh`: `pushd "$script_dir"` before the `cd ../../`, `popd` at the end, so GNUstep is checked out and built at the repository root rather than two levels above the caller's directory.
- `src/Core/OOFoundation.h`: moves `#import <Foundation/Foundation.h>` (and `<math.h>`, `<stdbool.h>`) above the `NDEBUG` → `NS_BLOCK_ASSERTIONS` block (upstream issue #757). The effect: gnustep-base's include-guarded exception header is parsed before `NS_BLOCK_ASSERTIONS` is defined, so `NSAssert`/`NSCAssert` stay live in the deployment flavour. Before the PR, clang-format had reordered the includes, the assertions were compiled out under `NDEBUG`, and the side effect inside `PlayerEntity -deferredInit`'s assertion (the player's ship set-up) was skipped, so the deployment build launched from the station wrongly.

## Tests
- `tests/unit/oofnd/test_objc_assert_ndebug.cpp` (registered at `tests/unit/oofnd/meson.build:93`) compiles `OOAssert.h` with `NDEBUG` defined in every flavour and checks that the condition and its side effects are evaluated and a false condition still raises. Its header comment names this exact failure (`PlayerEntity::deferredInit`).
- The `deployment_unit_tests` meson option (`meson.options:48`, used in `meson.build`) builds the oofnd suite under the deployment macros.

## Findings
1. The `#define NS_BLOCK_ASSERTIONS 1` at `src/Core/OOFoundation.h:45-47` is vestigial: no code at HEAD reads it. Harmless; mentioned only so that nobody later wires `OOAssert.h` to it, which would reintroduce #757.

## Why this verdict
The script and manifest parts pinned GNUstep, which the fork legitimately removed. The one behavioural part, assertions staying live in deployment builds, is kept by `OOAssert.h`'s design and pinned by an `NDEBUG` unit test.
