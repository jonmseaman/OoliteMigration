# Upstream #766: Native Apple Silicon macOS build: app bundle, DMG installer and CI

**Upstream:** David Hobley (hobleyd), merged 2026-10-26 as `65e46ed6e` (merge; diff `9ee8ff22f..65e46ed6e`) · **In the stack:** base; its code is carried by the conversion steps (`a7764d6a9`, `ff8664462` and the slices; summary in `167118dff` "Port upstream #766, #774 and #781"), `f18e064bc`/`8f62d84da` for the guards, `e53956d71` and `167118dff` for packaging, `a78613a9d` removes the `OOLITE_MAC_OS_X` blocks
**Verdict:** Regression (from reading the code; macOS runtime not verifiable here)

The regression is narrow: where a macOS build keeps its logs, add-ons, cache and preferences (Finding
1). The rest of #766 (GL 2.1, the shader translator, the MSAA renderbuffer, high-DPI input, the
bundle, DMG and CI) is ported or legitimately superseded.

## What the PR changes

Build and packaging
- `src/meson/darwin/meson.build` + `darwin.ini` (Apple clang/ld64); `mk.sh` picks `darwin.ini` on
  Darwin and re-executes under Homebrew bash 4+; `pkg-dmg` target; `@executable_path` rpath; no
  `--thinlto-cache-dir` on Darwin; Info plist embedded with `-sectcreate`.
- `post_build.sh` builds `oolite.app/Contents/{MacOS,Resources,AddOns,Frameworks}`, an `Info.plist`
  from `Info-gnustep.plist` minus Cocoa keys, bundled `@rpath` dylibs, ad-hoc signature
  (`create_app_bundle_fn.sh`); `installers/macos/create_dmg_fn.sh`; `install.sh` copies to
  `/Applications/Oolite.app`; GNU `date`/`cp` and BSD `wc` handling in the version scripts.
- SpiderMonkey for arm64 (`build_mozilla_js.sh`, `mozilla_js_arm64.patch`), `-DXP_UNIX -DXP_MACOSX`,
  Apple Foundation framework, `-fblocks`, no `-DGNUSTEP_BASE_LIBRARY` on Darwin.
- CI: `build-macos` job (three flavours, DMG artifacts, release count 8 → 11,
  `contents: write`), `test_builds.yaml` `macos` job; smoke test uses a real window on macOS.

Platform macros
- On Apple Foundation + SDL, `OOLITE_MAC_OS_X` and `OOLITE_SDL` are both 1; new
  `OOLITE_MAC_COCOA_UI` (= `OOLITE_MAC_OS_X && !OOLITE_SDL`) guards the Cocoa leftovers (≈40 sites:
  GameController, key-mapper `mod2` text and `keymappings_mac.plist`, speech rows, display-style
  row, iTunes, CGL macros, OXP-verifier log opening, `ResourceManager +builtInPath`, extension
  manager lock). `OOLITE_MAC_OS_X` keeps selecting OS-level behaviour: log, cache and add-on paths,
  plist handling.
- `OODebugMonitor -applicationWillTerminate` and the GameController call move from
  `OOLITE_GNUSTEP` to `OOLITE_SDL`.

OpenGL (macOS legacy 2.1 context)
- Accept 2.1 with `ARB_framebuffer_object`, `APPLE_vertex_array_object`, `ARB_texture_float`,
  `ARB_color_buffer_float`, `ARB_draw_buffers`.
- `glGen/Bind/DeleteVertexArrays` → `*APPLE`, `glClampColor` → `glClampColorARB`,
  `GL_GLEXT_PROTOTYPES` and `<OpenGL/glext.h>` on Apple; MSAA colour buffer is a multisample
  renderbuffer (`OO_MSAA_COLOR_RENDERBUFFER`) in create, resize and delete.
- `OOGLProgramName()` (GLhandleARB is a pointer on macOS) in the post-processing pass; the blur
  loop uses the converted handle.
- `TranslateGLSL330To120()` for programs whose prefix starts `#version 330`; three shader files
  rewritten in GLSL 3.30 that the translator can handle.

SDL front end
- macOS: no `SDL_GetWindowSurface`; VSync via `SDL_GL_SetSwapInterval`/`GetSwapInterval`;
  snapshots read `GL_FRONT`, use a scratch `SDL_CreateSurface` of the pixel size, then restore
  `GL_BACK`; `setFullScreenMode:` under `OOLITE_SDL` instead of `GNUSTEP_BASE_LIBRARY`.
- All platforms: mouse warp and mouse-move scaled by `SDL_GetWindowPixelDensity`; window size
  saved in points (`SDL_GetWindowSize`); HDR snapshot name uses
  `stringByReplacingOccurrencesOfString:`.
- `main()`: on macOS `chdir` to the executable's folder, then up to `Contents` from
  `Contents/MacOS`.

Shared fixes
- `Station.addShipToShipyard` with no personality stored `nil`; now `0`.
- Debug console on macOS: plain non-blocking socket with a 3 s connect timeout (`getaddrinfo`,
  `AF_UNSPEC`), read only while bytes are available, keep the host string instead of `NSHost`.

## Findings

1. **Regression (macOS, code reading): the macOS file locations #766 used are gone.** In upstream's
   macOS build `OOLITE_MAC_OS_X` is 1 (`OOFoundation.h:57` at `65e46ed6e`: no
   `GNUSTEP_BASE_LIBRARY` on Darwin) and the #766 description states it "only selects Foundation and
   OS-level behaviour, such as log, cache and add-on paths and plist handling". The fork deleted
   those branches as dead (`a78613a9d`: "OOLITE_MAC_OS_X (always 0) … ~/Library log folder … the Mac
   cache file name"), so a macOS build at HEAD uses the POSIX/GNUstep layout:

   | | Upstream #766 on macOS | HEAD on macOS |
   |---|---|---|
   | Logs | `~/Library/Logs/Oolite`, excluded from Time Machine (`OOLogOutputHandler.m:563-594`) | `LogBasePath()` has branches only for `OOLITE_LINUX` and `OOLITE_WINDOWS` (`src/Core/OOLogOutputHandler.cpp:310-319`); on macOS `path` stays empty and `AppendPathComponent("", "Logs")` gives `"Logs"`, relative to the cwd `main()` set, i.e. `oolite.app/Contents/Logs` (`:322`). `tests/launch_snapshot.py:358-359` already skips a `Logs` sibling in the bundle |
   | User AddOns | `~/Library/Application Support/Oolite/AddOns`, `<folder holding oolite.app>/AddOns`, `Contents/AddOns`, `~/.Oolite/AddOns` (`ResourceManager.m:171-183`) | `<cwd>/../share/oolite/AddOns`, `Contents/AddOns`, `~/.Oolite/AddOns` (`ResourcePaths.hpp:241-247`, `:205-213`) |
   | Managed (OXZ) AddOns | `~/Library/Application Support/Oolite/Managed AddOns` (`OOOXZManager.m:226-235`) | `~/GNUstep/Library/ApplicationSupport/Oolite/ManagedAddOns` (`ResourcePaths.hpp:199-203`; `applicationSupportDirectory()` is `~/GNUstep/Library/ApplicationSupport`, `:191-196`) |
   | Data cache | `~/Library/Caches/org.aegidian.oolite/Data Cache.plist` (`OOCacheManager.m:262-282,565-570`) | `~/GNUstep/Library/Caches/org.aegidian.oolite/Oolite-cache.plist` (`src/Core/OOCacheManager.cpp:245-265,537`) |
   | Preferences | `NSUserDefaults`: `~/Library/Preferences/oolite.plist` | `~/GNUstep/Defaults/oolite.plist` (`src/oofnd/Defaults.hpp:427-435`) |
   | Saves | `~/oolite-saves` | `~/oolite-saves` (`ResourcePaths.hpp:173-176`) — same |

   Consequences: a macOS player of an upstream #766/#781 build would not find their add-ons, OXZ
   downloads or settings after moving to a build of the stack; and logs are written inside the app
   bundle, which fails where the bundle is read-only (a mounted DMG, Gatekeeper's translocated copy)
   and adds files under a signed bundle. `src/oofnd/ResourcePaths.hpp:45-46` still says "The macOS
   (Cocoa) layout is not reproduced: that platform is not supported", which no longer matches a
   tree that builds a macOS bundle. The migration repo already records this as open
   (`notes/2026-11-07 Cross-Platform Correctness.md` item 4, measured on a later branch). Fix: add a
   `macos` `PathEnvironment::Platform` (Library/Logs/Oolite, Application Support/Oolite/AddOns and
   Managed AddOns, Caches, the bundle-sibling AddOns folder) and a `OOLITE_MACOS` branch in
   `LogBasePath()`, with `test_resourcepaths` cases; preferences need a decision (a binary
   `~/Library/Preferences` plist vs. the fork's OpenStep writer).
2. **Deviation (macOS console connect).** HEAD resolves IPv4 only (`hints.ai_family = AF_INET`,
   `OODebugTCPConsoleClient.cpp:435`) and has no connect timeout; upstream's macOS path used
   `AF_UNSPEC` and gave up after 3 s. With the default `127.0.0.1` console this changes nothing; with
   an unreachable `debug-console-host` the game waits for the OS connect timeout at startup. The
   comment at `:257-261` documents the same wait as GNUstep's measured behaviour, which is what HEAD
   applies on every platform.
3. **Deviation (UI on macOS, arguably a fix).** Upstream's SDL macOS build still had
   `OO_RESOLUTION_OPTION 0` (`PlayerEntity.h:108-112` at `65e46ed6e`, under
   `OOLITE_MAC_OS_X && OOLITE_64_BIT`) and skipped the full-screen Cmd-F/Cmd-Q handling
   (`PlayerEntityControls.m:883`, "handled by normal menu shortcuts", which the SDL build has none
   of). HEAD shows the resolution row and handles those keys on macOS, as on Linux. Different from
   upstream's runtime, but the upstream behaviour is a Cocoa leftover #766 did not reach.
4. **Shared gap, not a regression.** `keymappings_mac.plist` is not used on SDL macOS either
   upstream (`OOLITE_MAC_COCOA_UI` only) or at HEAD (`PlayerEntityKeyMapper.cpp:147-156`); the
   keyboard-layout list is empty there in both.
5. **Not verifiable here:** whether libc++ on the macOS runners supports
   `std::regex::multiline` (used by the translator, `OOShaderProgram.cpp:589`), the GL 2.1 context
   path, the front-buffer snapshot, and the Retina mouse scaling all need a Mac. The code at HEAD
   matches upstream's for each.

## Why this verdict

Hunk for hunk, #766's GL, shader, SDL, packaging and CI changes are at HEAD and equivalent, and
the SpiderMonkey and Apple Foundation parts are superseded by rule 6. But #766 also made the macOS
build use macOS's own locations for logs, add-ons, OXZ downloads, the cache and preferences, by
keeping `OOLITE_MAC_OS_X` on for exactly that. The fork treats `OOLITE_MAC_OS_X` as always 0 and
deleted those branches, and nothing macOS-specific replaces them: macOS falls through to the
GNUstep/POSIX layout, and for logs to a relative folder inside the bundle. Merged upstream, that
would move existing macOS players' data. This is from reading the code; none of it was run on a Mac.
