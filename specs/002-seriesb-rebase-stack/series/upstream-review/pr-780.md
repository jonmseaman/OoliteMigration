# Upstream #780: Use engine-neutral JavaScript names outside the scripting layer

**Upstream:** hobleyd (David Hobley), merged 2026-11-01 as `7437f22a5` (squash; first half of #767, issue #580) · **In the stack:** base (every conversion step carries it); script events pinned by `test_EntityScriptEvents` (`9dfcc4cb5`)
**Verdict:** Ported correctly

## What the PR changes

Mostly renames (`jsid` -> `OOJSPropID`, `jsval` -> `OOJSVal`, `uintN` -> `int`, `JSBool` -> `BOOL`)
in 21 files outside `src/Core/Scripting`. The behavioural parts:

1. New helpers (`OOJSValueFromDouble`, `OOJSValueToBOOL`, `OOJSValueToInt32`,
   `OOJSUndefinedValue`, `OOJSNullValue`, `OOJSValueIsUndefined`, `OOJSReportPendingException`,
   `OOJSFreeValue`) in `OOJavaScriptEngine.h`; `OOJSPropID` in `OOJSPropID.h`.
2. Ownership: callers free the values they create; `ShipScriptEvent()` frees its arguments after
   the event; `ShipScriptEventNoCx()` acquires a context and forwards to `ShipScriptEvent()`;
   `doScriptEvent:withArgument:(andArgument:)` free their converted values. `argv` passed to
   `doScriptEvent:...withArguments:count:` and `doWorldScriptEvent:` is borrowed.
3. Events that used `ShipScriptEventNoCx` with constants now use `doScriptEvent:withArgument:`
   with the same JS values: `playerWillSaveGame` (`AUTO_SAVE`, `QUICK_SAVE`, `STANDARD_SAVE`),
   `playerJumpFailed` (`malfunction` x2, `blocked`, `no target`, `too far`,
   `insufficient fuel`), `alertConditionChanged` (player and station, new then old as numbers),
   `entityDestroyed` (no arguments).
4. `INT_TO_JSVAL`/`JS_NewNumberValue` -> `OOJSValueFromDouble` and
   `STRING_TO_JSVAL(JS_InternString(...))` -> `OOJSValueFromNativeObject` in `infoSystemWillChange`,
   `infoSystemChanged`, `mfdKeyChanged`, `selectedMFDChanged`, `shipBountyChanged` (x4),
   `compassTargetChanged` (undefined, mode), `shipWillEnterWitchspace` (x4, cause string and
   destination), `shipTakingDamage`, `shipHitByECM`, the `coordinatesForEscortPosition` and
   `scriptedAI` calls and `updateLocalCommodityDefinition`.
5. `shipHitByECM`: the two argument values are created per target (the macro now frees them).
   `shipKilledOther`: the damage-type value is recreated after `shipDied` freed it.
6. Boolean callbacks read through `OOJSValueToBOOL` (false on conversion failure, default kept):
   `acceptDockingRequestFrom`, `acceptLaunchingRequestFrom`, `willOpenDockingPortFor` (x2),
   `allowShowLibraryShip`, `allowSpawnShip`, `allowOfferShip`, `allowAwardEquipment` (x2).
7. `updateEquipmentPrice`: reports the pending exception when the result is not an integer
   (`OOJSReportPendingException`); no longer checks `JS_NewNumberValue`'s return.
8. `ShipEntityAI` predicate scan: `OOJSReportPendingException` in place of
   `JS_ReportPendingException`. `OODebugMonitor -performJSConsoleCommand:` frees the command value.

## Why this verdict

#780 was behaviour-preserving on SpiderMonkey apart from the three small differences its
description lists, and each is at HEAD: `OOJSValueToBOOL` returns false without clearing `OK`,
`updateEquipmentPrice` reports a failed conversion, and the number creation is unchecked. The
ownership rules it introduced for QuickJS (free owned values, macro frees its arguments, `argv`
borrowed) are what HEAD implements with real `JS_FreeValue` calls, including the two places the
PR had to restructure (`shipHitByECM`, `shipKilledOther`). The events that moved to
`doScriptEvent` are tested with their arguments.
