# Contract: `test_OOSnapshotWriters`

A new program in the `core` suite (`tests/unit/core/test_OOSnapshotWriters.cpp`, entry `['*']`).
It is written on the same harness and in the same layout as the other `core` programs; spec 005
converts it later with the rest. It is added at M0 and must pass on the unmoved code before
anything moves (FR-011, SC-005).

## S1. Input

One fixed RGB float image, 40 × 3, defined as literals in the test:

- row 0: a ramp of ordinary values in (0, 4], including exactly 1.0 and 0.5;
- row 1: zeros, a pixel with one negative component, and a pixel with all three negative;
- row 2: large finite values up to 65504 (the largest half), and small ones near 1e-3.

No infinities or NaNs (spec edge case: stb v1.17 handles infinities differently from v1.16, and the
game never writes them).

## S2. `.hdr` (every host)

1. Write with `stbi_write_hdr(path, 40, 3, 3, data)` from the game's `MyOpenGLView.cpp` object, to
   a file in the test's temporary directory. Expect a nonzero return.
2. Decode with the test's own reader: the `#?RADIANCE` header, `FORMAT=32-bit_rle_rgbe`, the
   `-Y 3 +X 40` line, then flat or new-style run-length scanlines. stb uses run-length scanlines
   for widths 8 to 32767.
3. For each pixel with largest input component `m` > 0: each decoded component is within `m / 128`
   of `max(input, 0)`. A negative input component decodes as exactly 0. A pixel whose components
   are all ≤ 0 decodes as (0, 0, 0).

## S3. `.exr` (Windows only)

1. Write with `SaveEXRSnapshot(path, 40, 3, data)` from the game's `OOSaveEXRSnapshot.cpp` object.
   Expect 0 (`TINYEXR_SUCCESS`).
2. Parse the header with `ParseEXRVersionFromFile` and `ParseEXRHeaderFromFile`:
   - compression is ZIP;
   - three channels named B, G, R stored as half;
   - one custom attribute named `signature` of type `string`, whose value begins
     `Generated by Oolite `.
3. Load with `LoadEXRImageFromFile` requesting the stored half type. Each half equals the input
   converted to half by round-to-nearest, ties-to-even. The test does that conversion itself and
   does not call tinyexr's.
4. Free tinyexr's allocations with its own `Free*` calls.

## S4. Failure rules

- A failed check is reported with the pixel, the component, and the expected and actual values.
- If S3.3 fails on the unmoved code (old tinyexr's rounding differs), the expected halves of the
  failing pixels are replaced, at M0 only, by develop's decoded values. They go in as literals with
  a comment naming the reason. After M0 the test is not edited (hard rule 1).
- If S2 fails on the unmoved code, the work stops and reports: the bound or the reader is wrong, and
  neither is loosened to pass.
- After the move, any failure stops the work and names the library.
