# Re-bless approvals — the ONLY way a change under a protected golden path passes
# tools/guardrails.sh (CLAUDE.md rule 1, docs/phases/0-safety-net.md item 0.11).
#
# Protected paths today: goldens/ and tests/golden/scenarios/.
#
# Re-blessing a golden is Jon's decision alone. An agent that believes a golden is wrong says so
# with a justification and stops; it does not edit the golden and it does not edit this file.
# The guard enforces that mechanically: a change that edits BOTH a protected path AND this file
# is refused, whatever it says here. An approval is therefore always a separate, human,
# reviewed commit that lands BEFORE the re-bless, which is what makes it an approval rather than
# a note the same agent wrote to excuse itself.
#
# FORMAT: one line per approved path. The line MUST START IN COLUMN ONE - an indented line is
# NOT an approval, deliberately, so that a live approval cannot hide inside what every reader
# takes for the example block below. First whitespace-separated field is the path, exactly as
# git reports it; the rest of the line is free text and should say who approved it, when, and
# why. Blank lines and #-comments are ignored. A directory prefix is NOT accepted: an approval
# names one file, so it cannot be widened by accident or inherited by the next change.
#
# EXAMPLE (every line of it is a comment, and it is indented as well - two independent reasons
# it cannot be mistaken for a live approval by the guard):
#
#   tests/golden/scenarios/001/scenario.json   Jon 2026-09-20, re-bless queue: settle time
#                                              raised to 12 s after the run-loop fix.
#
# Approvals on record (remove a line once its re-bless has landed):
goldens/windows-x64/001/provenance.json   Jon Seaman 2026-09-18, oo-5ggu: provenance-only change from the -ffp-contract=off rebuild (verified=true, translation_units 242->243, build_dir); state.json is byte-identical, so no golden value moves.
